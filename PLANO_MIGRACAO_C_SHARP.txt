------------------------------------------------------------------
2. DECISÕES DE ARQUITETURA (fixadas)
------------------------------------------------------------------
1. Linguagem/UI: C# + WPF (.NET 8)  (não WinUI 3)
   Motivo: WPF é mais maduro para exe único self-contained, NotifyIcon
   (bandeja) trivial, ResourceDictionary espelha bem o QSS, e o
   empacotamento single-file é bem documentado.
2. Dados do usuário: %APPDATA%\OrganizadorPessoal com migração
   automática na primeira execução (lê arquivos ao lado do exe/
   workspace e copia para %APPDATA%). Corrige o design atual de
   gravar no diretório do programa.
3. Formatos de dados: manter 100% iguais aos atuais
   (lembretes.txt, tarefas.txt, notas.json, compras.json,
   estado_noticias.json) para preservar dados e permitir comparar
   versões durante a migração.

8. RISCOS E MITIGAÇÕES
------------------------------------------------------------------
1. Playwright.NET x single-file: o driver node não se funde bem no
   exe único. DECISÃO NA FASE 5:
     (a) WebView2 (embutido no Win11/Edge; usa JS para extrair preço
         após renderizar anti-bot) -> RECOMENDADO para exe único;
     (b) Playwright.NET -> paridade total, mas exige desempacotar o
         driver na 1a execução.
   Manter requests + HtmlAgilityPack como camada primária e o
   navegador só no fallback.

2. Fidelidade visual QSS -> WPF: estilos QSS não têm seletor de
   propriedade; resolver com DataTrigger. Validar card a card por
   pixel nos 2 temas (padrão atual).

3. FontAwesome: embutir fonte FA5 (licença OFL, livre) e mapear os
   ~40 nomes fa5s.* usados.

4. Registro QSettings: leitura única e idempotente; nunca regravar.

5. Perda de dados na migração: copiar antes de gravar; nunca apagar
   os arquivos originais.

6. Esforço: reescrita total ~8,5 k LOC Python -> estimativa realista
   de 3 a 6 semanas de trabalho focado, fase a fase, mantendo o app
   Python funcionando até a Fase 6 (coexistência).
